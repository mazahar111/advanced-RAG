Title: Person-to-person electronic payment processing
Abstract: A method of person-to-person anonymous electronic payment processing involves a payment processing server receiving from a payor payment device a payment initiation request for a payment from a payor account. The payment initiation request identifies a payment amount and excludes payee particulars and the payee account. The server also receives from a payee payment device a payment completion request requesting completion of the payment. The payment completion request includes a payee identifier and excludes the payment amount, payor account and payor particulars. The server confirms that the payment completion request is uniquely associated with the payee payment device and the payee identifier, and determines the payment amount and the payor account by correlating the payment completion request with the payment initiation request. In accordance with an outcome of the confirming, the payment processing server effects a transfer in the payment amount from the payor account to the payee account.

Description: CA 02851895 2014-05-08PERSON-TO-PERSON ELECTRONIC PAYMENT PROCESSINGFIELD OF THE INVENTION[0001] This patent application relates to a method and network for processing electronic payments.BACKGROUND[0002] To make a person-to-person electronic payment, a payor may initiate an e-payment transfer through the payor's financial institution server. Using a web portal or a dedicated software application, the payor provides the payor's financial institution serverwith the intended payment amount, the payee's e-mail address or phone number, and asecurity question and answer. The financial institution server issues to the payee an e-mail or text message that includes a link to the pending transaction, and identifies the payment amount and the payor. To accept the payment, the payee uses its computing device to select the transaction link, which causes the payee to authenticate to the payee'sfinancial institution account and to be prompted for an answer to the security question. Ifthe security answer provided by the payee corresponds with the security answer provided by the payor, the payor's financial institution server effects a payment transfer from the payor's financial institution account to the payee's financial institution account.[0003] Although e-payment transfers are convenient, to receive the payment thepayor must be provided with personal information of the payee (e.g. e-mail address,phone number, answer to security question), and the payee receives personal information (e.g. name, e-mail address) of the payor. The payee could provide the payor with a generic e-mail account address or the phone number of a disposal mobile phone. However, the payee may wish not to provide the payor with any such personalinformation. Moreover, e-payment transfers may be subject to man-in-the-middle attacksthat can intercept the payee's security answer, and direct the payment to an unauthorized account.[0004] Schattauer (US 8,423,457) describes using mobile devices to effect anelectronic payment, without the payment provider or recipient exchanging personal- 1 -CA 02851895 2014-05-08information. Using its mobile device, the provider transmits to a host computer an anonymous payment request that identifies the payment amount. In response, the host computer sends the provider's mobile device a unique code that allows the recipient tomaintain anonymity. The unique code may include a portion of the recipient's information. The provider provides the unique code to the recipient.[0005] The recipient uses its mobile device to transmit the unique code to the hostcomputer, together with information that is unique to the recipient. The host computer associates the unique code with the unique recipient information, but the payment may be disassociated from the provider. The host computer effects the payment by updating thefinancial accounts associated with the provider and the recipient.[0006] Although the payor and payee need not exchange personal information, thepayment transfer may still be subject to man-in-the-middle attacks that can intercept the payee's unique code and direct the payment to an unauthorized account. This deficiency may be addressed by the provider adding the recipient's information to the unique code,at the expense of anonymity.SUMMARY[0007] This patent application discloses a person-to-person e-payment processingserver and associated method that processes electronic payments without exchanging personal information between payor and payee.[0008] In accordance with a first aspect of the disclosure, there is provided a methodof person-to-person electronic payment processing that involves a payment processing server receiving from a payor payment device a payment initiation request for a payment from a payor account.
